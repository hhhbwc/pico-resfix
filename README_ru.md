# PICO 2D Resolution — Мод для изменения разрешения виртуального дисплея приложений

Модуль для разблокировки разрешения 2D-приложений на **PICO 4 Standard Edition (A8110, Android 10 / API 29)**.
Позволяет **настраивать для каждого приложения** разрешение 2D виртуального дисплея (больше не ограничено 1600×900), устанавливать пользовательское значение DPI и переключать выбранные приложения из режима парящего окна (Far-field) в режим Dock (Near-field).

Реализовано с помощью инъекции в `com.picovr.systemext` через **Zygisk Vector (совместимый с LSPosed фреймворк)** — замена системных APK не требуется.

**Текущий выпуск: v1.16**

---

## Предварительные условия

- **Устройство**: Шлем Pico 4 (поддерживаются прошивки Phoenix/China).
- **Права доступа**: Требуется **Root-доступ** ([Руководство](https://pico4.wiki/guides/root/01-root/)) для применения изменений к системным файлам.
- **Окружение**: **Magisk** + **LSPosed Framework** ([Zygisk Vector](https://github.com/JingMatrix/Vector)) должны быть установлены и активны.
- **Область действия LSPosed**: Убедитесь, что в области действия модуля LSPosed выбран `com.picovr.systemext`.

## 1. Возможности

| Параметр | Оригинал | Разблокировано |
|---|---|---|
| Разрешение 2D-приложений | 1602×902 (плотность 200) | **Настраивается для каждого приложения** (По умолчанию 2560×1440) |
| DPI | Фиксировано 200 | **Настраивается для каждого приложения** (Опционально) |
| Режим окна | Определяется APK: Floating или Dock | **Принудительно Floating или Dock для каждого приложения** |
| Область действия | Все 2D-приложения | **Включено по умолчанию для пользовательских приложений, опционально для системных** |

- Изменяет только разрешение (px) + опционально DPI. **Без изменения плотности (density) это приводит к суперсэмплингу, сохраняя соотношение сторон.**
- Независимая конфигурация для каждого приложения.

## 2. Архитектура

```
PICO 4 (Android 10, API 29)
└─ Magisk + Zygisk Vector v2.2 (LSPosed-совместимый фреймворк)
   └─ Этот модуль com.picoxr.resfix (mid)
       ├─ LSPosed хук: ResFix
       │    хукает метод com.picovr.systemext
       │    AppContainer.createVirtualDisplay(String,int,int,int,int)
       │    → Разбор "NS_APP[<pkg>]" → Поиск конфига по имени пакета → Переопределение w/h(/density)
       │    AppManagerUtils.getWindowType(ActivityInfo)
       │    → Возвращает "near" (тип 2002) для Dock-приложений
       └─ GUI: AppListActivity + AppDetailActivity
            (Список приложений + настройки разрешения)

Путь к конфигу: /data/local/tmp/resfix.cfg (JSON)
  - Записывается GUI-приложением (нужен root)
  - Считывается хуком ResFix через проверенный версионированный снимок конфигурации
```

---

## 3. Почему хук, а не замена APK?

- `SystemExt` — это PERSISTENT системное приложение с `sharedUserId="android.uid.system"`. Замена APK на самоподписанный будет отклонена PackageManager. Поэтому используется LSPosed хук.

---

## 4. Формат конфигурации (/data/local/tmp/resfix.cfg)

```json
{
  "default": { "w": 2560, "h": 1440, "density": 200,
               "applyThird": true, "applySystem": false },
  "apps": {
    "com.example.app": { "w": 1920, "h": 1080, "density": 240, "dock": true }
  }
}
```

- `apps.<pkg>.dock`: `true` направляет приложение в нативный Near-field Dock (тип 2002); `false` принудительно включает обычное Far-field Floating окно (тип 3002), включая приложения, ранее преобразованные Pico2Dock. Эта настройка независима от переопределения разрешения.
- Ширина допускается от 320 до 7680 px, высота от 240 до 4320 px, density от 72 до 1000. Неверные, неполные или неправильно типизированные записи отклоняются до передачи в SystemExt.
- Конфигурация ограничена 500 приложениями и размером 256 KiB. При некорректном значении `Settings.Global` хук использует файл конфигурации; если оба источника недоступны, сохраняется последняя действительная конфигурация.

После изменения настройки отдельного приложения используйте **Apply & Restart App**, чтобы сохранить настройки и перезапустить выбранное приложение. Обычная кнопка **Save** только записывает конфигурацию. Для настроек по умолчанию приложения необходимо перезапустить вручную.

## 5. Сборка

Требования: JDK 17 + Android SDK (platform 34, build-tools 34). Используйте Gradle Wrapper из репозитория: он выбирает версию Gradle для проекта.

```bash
./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest
```

---

## 6. Развертывание

1. `adb install -r app-debug.apk`
2. Обновите путь `apk_path` в базе данных модулей LSPosed
3. `adb reboot` (Vector заново просканирует модули)
4. Откройте "PICO 2D Resolution" → Список приложений → Выберите приложение для настройки разрешения и режима окна
5. Используйте **Apply & Restart App**, чтобы сохранить настройки и сразу перезапустить приложение

---

## 7. Версионирование

`versionName` Android, Git tag, название GitHub Release и имя APK используют один номер версии. Например, v1.16 публикуется с тегом `1.16` и файлом `Pico-ResFix-v1.16.apk`.
